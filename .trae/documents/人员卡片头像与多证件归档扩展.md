# 实施计划：卡片头像 + 一人多证互补 + 三类人员/其他证书支持

## Context（背景）

用户对「特种作业人员管理」模块提出三项新需求：

1. **卡片视图显示人员头像照片**——当前卡片左上角 `.pln-file-ico` 只显示工种短名，人员档案（swList）无照片字段。
2. **一人一次上传多个证件、信息相互补充**——当前 `swMatchWorker`（L14005）要求 idCard/name 与 **trade 同时相同**才匹配同一人，同人持有不同类别证书（如电工证 + 安全员C证）会被拆成两个档案，字段无法互补。
3. **支持三类人员证（安全 A/B/C 证）及其他证书的识别与归档**——`SW_TRADES`（L12840）仅含 8 种特种作业工种，解析器 `swParseCertText`（L13510）识别不出三类人员类别，证书编号正则（L13530）不匹配 `(京)建安C(2024)0012345` 这类含括号格式。

**两个已定设计取向**（审批时可调整）：
- 头像来源 = 编辑表单内**手动上传/粘贴**（复用隐患治理模块 L5159-5198 的读图+canvas 压缩模式），不做人脸自动截取。
- 三类人员/其他证书**并入现有人员档案体系**（一人多证），归档目录按「该证书自身类别 · 单位」分文件夹，不新建独立模块。

## 改动文件

仅 `综合安全管理系统.html`（单文件离线系统）。**注意**：L3500-3580 表单 HTML 与 L13817 附近存在历史"swUp+Edit 组合"token 区域，凡涉及这些区间只做行号定位的**插入**，不重写既有行；大块编辑走"临时文件 + PowerShell 正则发现占位符注入"的既定模式。

## 实施步骤

### 一、头像（需求1）

1. **压缩函数**：新增全局 `swCompressAvatar(dataUrl, cb)`，仿 `govCompressImage`（L5271-5289）：canvas 方形裁切 → 160px → JPEG q0.75（约 8-15KB/张，控 localStorage 体积）。
2. **数据字段**：
   - `swCreateWorker`（L14029）与 `swSaveForm`（L14239）的 data 增 `photo: ''`；
   - `swOpenForm`（L14121）读入表单，`swSaveForm` 写回；
   - `swMergeWorker`（L14050）加 `if (!w.photo && row.photo) w.photo = row.photo;`；
   - 旧数据无 photo 天然兜底（渲染判空）。
3. **卡片渲染**：`swRenderList` 卡片段（L13083-13105），`.pln-file-ico` 改为：有 photo 渲染 `<img>`（object-fit: cover、圆角继承），无 photo 保持 `t.short` 文字。样式补 `.pln-file-ico img`（约 L1148 附近）。**台账表格不加**（用户只要求卡片）。
4. **表单/详情 UI**：
   - 档案表单 `pen-form-grid`（L3508）前插头像块：~64px 预览 + 隐藏 `input[type=file]`（`opacity:.01` 覆盖，沿用上传控件自动化惯例）+ 粘贴按钮（`navigator.clipboard.read` → FileReader → `swCompressAvatar`，不复用 govPasteTarget 全局避免与隐患模块互扰）+ 删除头像按钮；
   - `swOpenDetail`（L14320）详情标题区显示头像。

### 二、一人多证互补（需求2）

5. **放宽 `swMatchWorker`（L14005-14028）**：
   - idCard 非空且与档案相同 → 同一人（**去掉 trade 相等条件**，合并原"补 trade"分支）；
   - 无 idCard：name 相同且（trade 相同 **或** 任一方为空）→ 同一人；
   - 同名无身份证且 trade 均非空且不同 → 不合并（防同名误并），`swSaveForm` 的同名确认（L14270）保持。
6. **互补语义**：`swMergeWorker` 不改——空缺字段填充、validTo 取更晚者、**不覆盖已有值（含 trade，档案保留先到类别）**；归档目录按各证件自身 `row.trade · unit` 分文件夹，`w.files` 聚合同人全部证件。同批多文件先后归档经 swList 天然递增互补。

### 三、三类人员与其他证书（需求3）

7. **`SW_TRADES`（L12840-12849）追加**（放在 other 之前，safeA 在 safeB/safeC 前）：
   - `safeA` 建筑施工企业主要负责人（A证），kw：安全生产考核合格、主要负责人；
   - `safeB` 项目负责人（B证），kw：项目负责人；
   - `safeC` 专职安全生产管理人员（C证），kw：专职安全生产管理人员、专职安全员；
   - 识别不出类别 → 既有 `other`（其他特种作业 → 名称可微调为"其他证书"需同步卡片/筛选文案，注意 other 的 name 被 `swTradeOf().name` 用作归档目录名，需检查所有引用点后统一改）。
   筛选器、徽标、目录、`swStatus` 自动复用该字典机制。
8. **`swParseCertText`（L13510）增强**：
   - 两轮 kw/name 匹配后增加**上下文正则兜底**：flat 含「考核合格|安全生产考核」时，`/(?:建安|安全)?\s*([ABC])\s*证/` → 映射 safeA/B/C；`A证/B证/C证` 单字母**不单独作 kw**，避免误伤；
   - **certNo 正则放宽（L13530）**：中文前缀后允许带括号段，如 `[\u4e00-\u9fa5]{1,6}(?:\([^)]{0,10}\))?`+ 内段，覆盖 `(京)建安C(2024)0012345`，保留"不等于身份证号"校验；
   - 其余字段（姓名/身份证/发证机关/有效期）现有正则已覆盖三类人员证常见版式。
9. **`SW_KINDS`（L12850）** 增 `{key:'safeCert', name:'三类人员考核证'}`，行表单证件类型下拉自动带上；上传弹窗说明文案（L3493-3495）与卡片空态（L13077）同步改为「人员档案 · 各类证书」口径。

## 风险与缓解

- **localStorage 体积**：photo ≤160px JPEG（8-15KB/人），数百人量级安全；严禁存原图。
- **同名误合并**：idCard 优先；name 分支要求 trade 相等或一方为空；人工表单仍保留同名确认。
- **ABC 正则误伤**：单字母不作独立关键词，仅在"考核合格/安全生产"上下文匹配；先跑误伤回归（电工/司机样本仍判原工种）。
- **token 发射不稳定区域**：仅按行号插入、占位符注入，不在 Edit old_string 中包含历史组合 token。
- **兼容**：不改 `swUpRowsData` 结构、OCR 单并发队列、对照编辑 touched 逻辑。

## 验证（本地 http.server + 无头 Edge 注入 harness，沿用既有成熟模式）

1. 头像：表单上传/粘贴 → `swCompressAvatar` 输出 ≤160px JPEG → swSaveForm 持久化 → 卡片 `.pln-file-ico img` 出现；无 photo 人员回退文字。
2. 一人多证：构造同 idCard、不同 trade 两行 → `swMatchWorker` 同档，files 累加、trade 保留先到、validTo 取最晚、归档目录按各自类别分文件夹。
3. 解析：注入含「安全生产考核合格证」「(京)建安C(2024)0012345」假 OCR 文本 → trade=safeC、certNo 含括号完整；「建筑起重机械司机」样本仍判 crane（无误伤）。
4. 全链路回归：上传 → 转图 → 识别 → 对照编辑 → 归档 → 卡片/详情展示，控制台零报错；完成后清理测试数据与进程。
