# 实施计划：作业类别按三大发证单位分类重排 + 自定义证件名称

## Context（背景）

用户要求理清特种作业三大发证单位（①住建厅/建委 ②市场监督管理局 ③应急管理局）各自对应的特种作业人员，按三单位**标准名称分类排列**更新系统的「作业类别」字典；**其他证件（如挖机操作证）支持自定义证件名称**。

现状：`SW_TRADES`（约 L12878）仅 11 条平铺（7 个建筑工种 + 安管三证 + 其他），无发证单位维度；筛选 chip（`swRenderCatbar` L13027）与表单下拉（`swTradeOptions` L13766）均平铺；"其他"只能显示固定名"其他证书"。

**兼容红线**：不改现有 11 个 key（存量档案 `w.trade`、已归档目录不受影响）；`other` 必须保持数组**末项**（`swTradeOf` L12913 未知 key 回退末项）；涉及含不稳定历史 token 的函数（`swRenderUploadForm` 等）只做行号定位插入，Edit old_string 不含该 token。

## 一、三单位 → 特种作业人员分类（定稿清单）

### 1. 住房和城乡建设厅 / 建设委员会（auth:'jz'，建筑施工特种作业 + 安管三证）
| key | 标准名称 |
|---|---|
| electric | 建筑电工 |
| scaffold | 建筑架子工 |
| signal | 建筑起重信号司索工 |
| crane | 建筑起重机械司机（塔式起重机/施工升降机/物料提升机） |
| craneInst | 建筑起重机械安装拆卸工 |
| basket | 高处作业吊篮安装拆卸工 |
| welding | 建筑焊工 |
| safeA / safeB / safeC | 三类人员：企业负责人A证 / 项目负责人B证 / 专职安全员C证 |

### 2. 市场监督管理局（auth:'sc'，特种设备作业人员，全部新增 key）
scAdmin 特种设备安全管理人员 · scBoiler 锅炉作业 · scVessel 压力容器作业 · scGas 气瓶作业 · scLift 电梯作业 · scHoist 起重机械作业（桥式/门式/行车）· scVehicle 场(厂)内专用机动车辆作业（叉车司机等）· scWeld 特种设备焊接作业 · scCable 客运索道作业 · scAmusement 大型游乐设施作业

### 3. 应急管理局（auth:'yj'，特种作业，全部新增 key）
yjElectric 电工作业(低压/高压/防爆) · yjWeld 焊接与热切割作业 · yjHeight 高处作业(登高架设/高处安装维护拆除) · yjCold 制冷与空调作业 · yjChem 危险化学品作业 · yjFirework 烟花爆竹作业 · yjMine 金属非金属矿山作业 · yjCoalGas 冶金煤气作业

### 4. 其他（auth:''，数组末项）
other = **其他证书**，选中后可**自定义证件名称**（如"挖机操作证"），显示与归档目录均用自定义名，为空时回退"其他证书"。

## 二、实施步骤（均在 综合安全管理系统.html）

1. **字典重排**（L12878-12911 `SW_TRADES`）：整体重写为「住建10 → 市监10 → 应急8 → other」，每项加 `auth`、新条目补 `short/color/kw`；`swTradeOf` 不动。新增常量 `SW_AUTHS=[{k:'jz',label:'住建厅/建委'},{k:'sc',label:'市场监督管理局'},{k:'yj',label:'应急管理局'}]` 与辅助函数 `swTradeLabel(o)`（`o.trade==='other' && o.tradeName` → tradeName，否则 `swTradeOf(o.trade).name`）。应急组 kw 注意：yjElectric 用 `['电工作业','低压电工','高压电工','防爆电气']`，不单写"电工"。
2. **筛选 chip 分组**（`swRenderCatbar` L13027-13041 + CSS L1126 附近）：「全部类别」后按 `SW_AUTHS` 三段循环，每段先插不可点灰色组标签（新增 `.pln-cat-grp` 样式），再遍历该组出 chip；other 放尾部无标签区；`swSetTrade` 逻辑不变。
3. **表单下拉分组**（`swTradeOptions` L13766-13772）：输出 `<optgroup label="住建厅/建委|市场监督管理局|应急管理局">` 三组 + 尾部裸 `other` option；调用方（L14004 上传行、L14186 档案表单）与 native `setVal` 兼容 optgroup，无需改。
4. **其他自定义名称联动**：
   - 上传行表单：`swRenderUploadForm` 中 trade 字段行（L14004）之后新增条件格：`r.trade==='other'` 时渲染 `data-fk="tradeName"` 文本输入（onchange 复用既有编辑回调名，**按占位符注入模式处理，不手打该 token**）；`swSyncForm` 同步 tradeName 值并按 trade 切换显隐。
   - 档案表单：HTML trade select（约 L3552 附近）旁加 `#swTradeName` 输入（默认隐藏），`swOpenForm` 赋值+显隐，select change 联显隐（新增 `swToggleTradeName()`），`swSaveForm` data 收 `tradeName`；`swMergeWorker` 补 `if (!w.tradeName && row.tradeName) w.tradeName = row.tradeName;`。
   - 显示统一改经 `swTradeLabel`：卡片 L13127、表格 L13159、详情 L14469、导出 L14693、归档目录 catName（swDoUpload 内 L14144 与 L14434 两处）。
5. **OCR 发证机关分组消歧**（`swParseCertText` L13553-13607）：先扫 flat 判组 `g`——住建词（住房和城乡建设/建设委员会/住建厅/建委/建筑施工特种作业）、市监词（市场监督管理/质量技术监督/质监）、应急词（应急管理/安全生产监督管理/安监）；name 轮与 kw 轮候选按「检出组优先 → 其余组 → other」排序（默认 jz 优先）；两轮结构、三类人员字母兜底、touched 逻辑保留。解决 kw 冲突（如"电工作业".indexOf("电工")=0 会被建筑电工抢走 → 靠 name 轮先命中 + auth 排序）。
6. **文案**：上传弹窗/空态提及"按发证单位分组"；组标签用短名，详情/说明用全称。

## 三、风险
- other 移位破坏回退 → 断言 `SW_TRADES[last].key==='other'`。
- kw 重叠误判（电工/起重机/焊工跨组）→ name 轮优先 + auth 排序 + 默认 jz；验证误伤回归。
- 新增约15条 chip 影响页面简洁 → 组标签 + 同行紧凑排布。
- 上传行表单含不稳定 token → 仅插入新行、占位符注入。
- 存量数据：仅新增 key，旧 key 不变；显示改经 swTradeLabel 后旧档案照常显示。

## 四、验证（http.server 8766 + 无头 Edge 注入 harness，沿用既有模式）
1. 字典：`SW_TRADES[SW_TRADES.length-1].key==='other'`、`swTradeOf('不存在').key==='other'`；每组条数 10/10/8/1。
2. 存量兼容：置 `w.trade='electric'` → 卡片/表格/详情/导出均显示「建筑电工」。
3. 筛选：catbar 含 3 个组标签；点市监 chip（如叉车）过滤正确；「全部类别」复位。
4. 下拉：`swTradeOptions('')` 含 3 个 optgroup + 裸 other；`select.value='scVehicle'` 可赋值（setVal 路径）。
5. 自定义名：上传行选 other 输入"挖机操作证"→ 归档 → 卡片 badge/表格/详情/目录名均显示"挖机操作证 · 单位"；为空回退"其他证书"。
6. OCR 消歧：issuer 含"应急管理"+文本"电工作业"→yjElectric；issuer 住建+"电工"→electric；无 issuer+"建筑电工"→electric；"压力容器作业"→scVessel；既有电工/起重/三类人员样本回归不误伤。
7. 全链路：上传→识别→对照编辑（other 联动输入）→归档→显示，控制台零报错；完成后清理测试数据与进程。
